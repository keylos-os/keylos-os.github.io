02 / THE DESIGN

Trust has a boundary.
So should software.

keylos is a Linux userland organized around capabilities, verified code, controlled effects, and recoverable state.

[ 01 ]

Scoped authority

Files, network destinations, secrets and budgets are granted explicitly. Labels track sensitive and untrusted inputs; the Rule of Two escalates dangerous combinations for review.

broker · vault · gate
[ 02 ]

Separate lifecycles

Verified code, signed configuration and writable data follow different rules. Reboot is designed to restore code integrity, while recovery deals with potentially hostile data.

depot · config · boot
[ 03 ]

Durable work

Loom records progress and recovers interrupted attempts. Resumed work gets fresh authority; uncertain external outcomes need reconciliation before another attempt.

loom · aide
[ 04 ]

Visible consequences

Signed receipts make important actions inspectable. Local transactions are designed for undo; external effects have explicit outcomes and compensation where supported.

ledger · strata

03 / BEYOND THE FIRST WORKBENCH

One foundation.
Many reasons to care.

The agent workstation comes first. The same architecture is intended to support these longer-term uses.

01

Developers with production keys

SECRETS & SUPPLY CHAINS+

Control which signed programs can use SSH, signing and production credentials. Give package scripts scoped access, and build toward hermetic, reproducible builds with transparent provenance.

vault / forge / tlog
02

People facing targeted attacks

PERSONAL COMPUTING+

Verified boot, phone-assisted verification before disk unlock, trusted approval surfaces and key-based deletion are intended for people handling sensitive material. These protections still depend on the kernel, firmware and a correctly integrated system.

boot / vouch / atrium / vault
03

Teams that need an audit trail

POLICY & EVIDENCE+

Signed, TPM-anchored receipts can provide evidence of grants, approvals and effects. Organizational approvals, data labels and fleet policy are designed to make handling rules enforceable and reviewable. Compliance depends on the deployment and its policies.

ledger / broker / fleet
04

Managed fleets and kiosks

OPERATIONS+

Build toward atomic A/B updates, signed declarative configuration, drift detection and attestation. Kiosk and guest profiles use constrained authority and ephemeral sessions.

courier / config / fleet / hearth
05

Servers and Kubernetes nodes

INFRASTRUCTURE+

Planned runtimes place pods in microVMs or run verified containers, with policy-controlled admission and attested node enrollment. Controlled egress and gateway credential injection reduce the secrets exposed to services.

cri / bench / gate
06

Software you don’t fully trust

COMPATIBILITY+

Legacy applications, Flatpaks and OCI images get a compatibility tier with explicit boundaries. The design also isolates removable media in a VM and gives web applications their own principals.

compat / bench / portals
07

Security research and teaching

A SYSTEM TO STUDY+

Explore capability-based security, transparent supply chains and durable agent execution using Linux mechanisms and shared, testable protocols. A reference system whose claims can be examined at the component boundaries.

protocols / conformance / Linux
