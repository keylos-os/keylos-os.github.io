# Contributing to the handbook

> How handbook pages and diagrams are written, laid out and checked. The handbook is plain Markdown plus generated SVG diagrams. A zero-dependency viewer (`index.html`) renders it with navigation and search.

## Layout

```
README.md, CONTRIBUTING.md        landing page and this guide
NN-<section>/README.md            section landing page: summary and a table of its pages
NN-<section>/<page>.md            pages
NN-<section>/<sub>/<page>.md      one optional level of subsections (for example runbooks/)
images/<name>.svg                 diagrams, generated by scripts/diagrams.py (committed)
scripts/diagrams.py               the diagram definitions and the SVG generator
scripts/gen_nav.py                builds nav.js (sections, pages, headings) for the viewer
scripts/check.py                  page checks (see below)
scripts/mdlib.py                  shared helpers: heading slugs identical to the viewer's
index.html, vendor/md.js          the viewer and its Markdown renderer
nav.js                            generated; do not edit by hand
Makefile                          serve, nav, diagrams, check, all
```

## Handbook pages and specs

The handbook explains. The specs decide.

| | Handbook page | Repository `spec.md` |
|---|---|---|
| Audience | Everyone: designers, implementers, reviewers, operators | The implementer of that repository |
| Voice | Explanatory, with rationale and diagrams | Normative (RFC 2119), numbered requirements |
| Scope | Cross-cutting topics and how pieces fit | One repository, self-contained |
| Source of truth | No. If a page and a spec disagree, the spec wins and the page is fixed | Yes. [protocols](../specs/protocols/spec.md) wins over every other spec for shared contracts |

## Writing pages

- Start with `# Title`, then a two- or three-line summary in a `>` blockquote. The checker enforces this.
- Write in the present tense, declaratively and concisely. Prefer tables to prose when comparing things.
- The product is **keylos** (lowercase). Components are repository names in lowercase: `warden`, `broker`, `gate`. Interfaces and methods use their schema spelling, for example `Broker.materialize`, `Gate.stage`, `TrustedPrompt.approve`.
- Mark components **specified (v1.0)**. Describe limitations neutrally in a short "Limitations" list.
- Link with relative paths:
  - other pages: `../06-security/secrets.md`
  - repository specs from a section page: `../../vault/spec.md`
  - repository specs from the docs root: `../vault/spec.md`
  - a spec section by its heading anchor: `../../protocols/spec.md#8-capability-tokens`
- Reference decisions by number with a link: [ADR-0008](11-decisions/adr-0008-host-executes-only-sealed-code.md).
- End every page with a `## Related` list.
- Never leave placeholders. The checker rejects the usual placeholder words.

## Terminology

Use the [Glossary](13-reference/glossary.md) terms consistently:

| Say | Not |
|---|---|
| principal | user, account (unless you mean a human) |
| generation | package, image (unless you mean an OCI image or an EROFS image specifically) |
| grant / token / capability | permission |
| materialize | open, resolve (for broker-mediated access) |
| effect, intent, mandate | action, request, approval token |
| workbench | sandbox, container |
| seal | sign (when the owner trusts code for the host) |
| receipt | audit log entry |
| tier 0 / 1 / 2 / 3 / legacy | trust level |

## Diagrams

All diagrams are generated by `scripts/diagrams.py`, a small deterministic SVG generator with boxes, groups, edges, notes, legends and sequence diagrams. Its output is byte-for-byte reproducible.

1. Add or edit a function in `scripts/diagrams.py` and register it in `DIAGRAMS`.
2. Use the role colours:

   | Role | Use for |
   |---|---|
   | `boot` | boot, courier |
   | `execution` | warden, bench, compat, devd, journal |
   | `authority` | broker, ledger, vault, hearth |
   | `state` | depot, strata, config |
   | `effects` | aide, gate, net |
   | `experience` | kish, atrium, portals |
   | `external` | off-machine infrastructure |
   | `kernel` | kernel, TPM, KVM |
   | `human` | people and their devices |

3. Lay boxes out on a grid so most edges are straight. In sequence diagrams, keep message labels to the method names of the schemas in [protocols](../specs/protocols/spec.md).
4. Run `make diagrams ONLY=<name>`, open `images/<name>.svg` in a browser, and fix any overlaps before committing.
5. Embed the diagram in a page with a relative image link, then add it to the [diagram gallery](13-reference/diagrams.md):

```markdown
![Authority flow](../images/authority-flow.svg)
```

## Checks

`make check` fails on:

- pages without a `# Title` and summary blockquote
- broken relative links, including links to repository specs and to heading anchors
- missing images
- SVGs that no page embeds
- forbidden wording: placeholders, and other projects' names

Run `make all` before every merge.
